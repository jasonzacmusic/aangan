Not today

1 · Code audit

It works — and the screen can lie for a whole take.

Checked live at 18:00: both devices check in (strip 57 s · screen 6 s), state audio_rec, note "Back at 4". The real work lives on branch cursor/studio-page-visible, 21 commits ahead of main — main has no display code at all. Two devices today: the old ESP32 "ledESP" drives the strip, the Waveshare drives the screen; both poll /api/door.

Bug · fixed, not deployedRelay throws away half the light's reports

api/door.ts accepts only ok / loud / door; the light sends six words (onair, wait, sos too). Recording, door opens → "door" stored. Door shuts → light says "onair" → rejected → the screen keeps flashing DOOR OPEN — please close it for the rest of the take.

accept all six words. One line in cloudflare/door-store/src/index.js, committed; needs a wrangler deploy — say the word.

BugScreen and strip can disagree for ~20 s

Strip polls every 15 s (its own comment still says 3 s); the screen only learns "door open" via strip → relay → screen. INVENTORY says the screen listens to the ESP-NOW broadcast — it does not; there is no espnow: block in door-display.yaml.

add the same espnow + packet_transport block to the screen so door/dBA arrive in milliseconds, like the strip.

MismatchTwo rulebooks

Strip goes amber WAIT when the room is loud even with nothing booked; screen shows green COME IN. The rules exist twice, in two files.

one rulebook — the strip's mark word becomes the screen's word.

StallA 400 ms poll with a 12 s timeout

ledESP hits 192.168.0.250 every 400 ms on a blocking client. The repo itself documents the mesh blocking that route; when it fails the board can freeze up to 12 s — fast flash stutters, relay poll starves.

only run it when ESP-NOW has been silent 5 s, with a 1 s timeout — or delete it.

Fixed todayState now lives in one place

At 17:51 the relay answered "store":"memory" — no store behind it, state split across warm serverless instances. Commit d24f7a1 (18:00) moved the door state into a Cloudflare Durable Object; the relay is now a thin proxy and returns 503 rather than inventing a blank state. Right call. The word-list bug above was copied into the Worker verbatim — fixed there too.

Cost≈1.05 M Vercel calls a month

Screen every 3 s ≈ 864k + strip ≈ 173k + the app. Hobby plan includes 1 M. Pro: 1 M included, then paid. Check the plan in the Vercel dashboard before adding a second screen.

MQTT push replaces polling entirely, and removes the 10-second TLS handshake the firmware comments complain about.

GoodWhat is right

Monotonic at/mat stamps; paint-on-change (no timer repaint) on the RGB panel; logger on native USB; the two-port trap documented. Keep all of it.

2 · The back of the board, explained

Every plug, what it is, what you can do with it.

From Waveshare's wiki and schematic, not guessed. Orientation as in your photo (USB ports on the left).

ASensor AD — plain GPIO6 with GND/3V3 next to it. This is your LED-strip data pin (through the 74AHCT125 already on order). Or a wired foot pedal. Or a beeper.
BI2C plug — same bus as the touch chip; 3.3/5 V selectable. Add a temp/humidity sensor, a light sensor, a keypad.
CUART USB-C — the flashing port (CH343). The small switch can reroute these two pins to the 3-pin UART header → plug a DFPlayer Mini MP3 module there for a chime or a voice line.
DUSB USB-C — power in, and the S3's own USB. This is the one you had it in when it "looked dead". Same pins as CAN; one or the other.
EmicroSD — SPI, chip-select on the I/O expander. Fine for logging, not usable for images in ESPHome today.
FRS485 / CAN — industrial bus terminals. Irrelevant for us; GPIO15 is a second usable pin if RS485 stays unused.
GBattery — JST PH2.0, single 3.7 V cell ≤ 2000 mAh, charges at 580 mA and runs the board alone (~3 h). No reverse-polarity protection — check the red wire against the silkscreen before plugging in.

3 · Layouts

Split screen, pictures, templates — yes, via LVGL pages.

ESPHome's LVGL component turns the screen into named pages, each with its own layout (grid/flex). The server sends one small JSON — {"page":"split","title":"ON AIR","img":"…/hero.png"} — and the screen switches page and fills the text. Images come from a URL into PSRAM; Indian-language text is rendered to a PNG on the server and sent the same way. A working LVGL config for this exact board exists (inytar's package) and needs ESPHome ≥ 2025.8 with display: mipi_rgb.

4 · Mounting

The panel is a Raspberry Pi 7" display in disguise.

Glass 192.96 × 110.76 mm, four M3 tabs at 126.2 × 65.65 mm centres — identical to the official Pi 7" Touch Display v1. So every bezel made for that fits the front; only the back differs. Waveshare sells no case for this board. Overall depth ≈ 17 mm; allow a 20 mm cavity.

Door sign recommended

  • Print Sergey Morozov's wall-mount case (Printables 1030369) in PETG via 3Ding or Robu's print service — ₹1,000–2,000, 24–48 h.
  • Screw the panel to the case back from inside via the tabs (M3×6 with a plate, or M3×10 into bosses — never long screws, they bottom on the glass). Front shows no fasteners.
  • Back plate on the wall; the sign lifts off on two screws for reflashing. USB-C out through a left-edge notch into raceway.
  • Or the carpenter's wooden bezel already in INVENTORY §6 — route a 193 × 111 rebate and a 155 × 87 window, offset 19 mm left / 13 mm top.
  • No printer, no carpenter: a Pi 7" v1 aluminium wall mount, blank the Pi openings, drill one USB-C slot.

Handheld only if you insist

  • colany V3 case on Cults3D has an 18650 bay — the safer cell for a gig bag. Billkater's slim shell + a 2000 mAh PCM Li-Po taped in a printed pocket is the flat option.
  • Runtime ≈ 3 h at full backlight; backlight can't be dimmed. For a full gig carry a USB-C power bank instead.
  • Pouch cells: rigid pocket, nothing pressing on it, room to swell, never charge sealed and unattended.
5 · The 20× menu

Where the leverage is, in order.

Now this board, this week

  • Merge the branch into main. Main is stale; GitHub is the source of truth.
  • Fix the relay word list (done on branch) and give the screen ESP-NOW so it flashes DOOR OPEN in milliseconds, not 20 s.
  • Move the strip onto GPIO6 of the Waveshare. One unit, one plug, retire ledESP to the drawer as a spare. Keep the strip short (the 12-LED ring or 1 m), separate 5 V supply, level shifter, use_psram: false on the LED buffer to avoid flicker.
  • Swap polling for MQTT. Mosquitto can run on chorale-pi (already owned) or a free hosted broker. Push, retained state, no TLS stall, zero Vercel invocations. This is the single change that makes everything after it cheap.
  • Convert the sign to LVGL pages. Today's big-word sign becomes page 1; split-hero and OTP become pages 2 and 3.

Next ₹200 – ₹2,000 each

  • Chime + voice line: DFPlayer Mini on the UART header, ₹150–250 + a small speaker. "Recording in progress" spoken when the door opens mid-take; doorbell tone; OTP received beep.
  • Touch on the sign: "Got it" for OTPs, "Knock" button that pings the studio, "Back in 10" presets — the screen already has 5-point touch nobody is using.
  • Pictures from Photo Hub: a poster URL per state — the week's workshop on the free screen, NSM logo on ON AIR.
  • Second screen at the G1 front door (same board, ₹4,299 at Hubtronics / ₹4,799 Robu) on the same MQTT topic family — the house board + OTP.
  • Wired pedal on GPIO6 of a spare board if you ever want a foot tap to advance a setlist on the screen — ₹400 sustain pedal, 10 lines of YAML, no pairing.

Later bigger screens

  • Waveshare ESP32-S3-Touch-LCD-7B, 1024×600, ~₹5.5–7k on Amazon.in — same YAML family, 60% more pixels. The sensible "bigger".
  • ESP32-P4 10.1" (1280×800), ~₹10–14k — video decode, 32 MB RAM, but ESPHome support landed only in 2026.2 and the 10.1" panels aren't in the model list yet. Six months.
  • History and alerts need a hub — that is the Pi, not a screen.

Not this board buy the right tool

  • Teleprompter: old iPad (owned) + AirTurn PEDpro / Donner BLE pedal (₹3–9k, Bajaao/Amazon.in) + TeleprompterPAD (### chapter markers, pedal jumps) or PromptSmart Pro (voice-following). "Intelligent" = generated from the nsm-script output, one chapter per YouTube chapter, tap times logged → chapter list for the upload. All trivial in a browser, impossible on ESP32. If the text must sit in the lens axis: a ₹300 70/30 glass hood, or Pi 5 + Touch Display 2 as a permanent rig.
  • Band pocket tablets: ₹10–12k Android or iPad mini + OnSong/forScore + the same pedal. PDFs, transposition, setlists, band sync — done. A custom ESP32 version only makes sense as a branded NSM product and still can't show a PDF or a Tamil lyric.
  • Anything with Bluetooth audio. The chip cannot.
